# คู่มือเขียนและอัปเดตงานใน Workboard

ใช้กับทุกคนที่ทำงานในโปรเจกต์ต่างๆ ทั้งทีมงานที่ใช้หน้าเว็บ และ AI agent ที่ใช้คำสั่ง `scripts/wb.mjs`
เป้าหมายคือเปิดงานใดก็ได้แล้วรู้ทันทีว่า **ทำอะไร เพื่ออะไร เหลืออะไร และถึงไหนแล้ว**

## 1. งานหนึ่งใบต้องมีอะไร

| ช่อง | เขียนอะไร | ใครเห็น |
| --- | --- | --- |
| ชื่องาน | สิ่งที่จะได้เมื่อเสร็จ เช่น "หน้าโทรออกแบบใหม่สำหรับทีมเทเล" ไม่ใช่ "แก้หน้าเทเล" | ทุกคน |
| ฟังก์ชัน | กลุ่มงาน/โมดูล เช่น "แอปเทเลและการโทร" | ทีม |
| สรุปสำหรับผู้ชมภายนอก | 1–2 ประโยคที่คนนอกทีมอ่านเข้าใจ: ทำอะไร เพื่อใคร ตอนนี้ถึงไหน **ห้ามเขียนแค่ตัวเลข เช่น "3 จาก 8 ขั้น"** | ทุกคน รวมลิงก์ผู้ชม |
| งานย่อย | ขั้นตอนที่ต้องเคลียร์ให้ครบ ข้อละ 1 สิ่งที่ตรวจได้ว่าเสร็จหรือยัง | ทุกคน (ผู้ชมเห็นชื่อข้อและความคืบหน้า ไม่เห็นโน้ต) |
| รายละเอียดและขอบเขต | ใช้แม่แบบด้านล่าง | ทีม |
| เกณฑ์ตรวจรับ | อะไรบ้างที่ต้องจริงก่อนถือว่าเสร็จ | ทีม |
| หลักฐาน | ลิงก์ commit / PR / หน้าจอ / ผลทดสอบ | ทีม |
| สาเหตุที่ติดขัด | ใส่เฉพาะตอนติดจริง งานจะขึ้นในหัวข้อ "ต้องการข้อสรุป" ของหน้าภาพรวม เคลียร์แล้วให้ลบออก | ทีม |
| ผู้รับผิดชอบ / กำหนดเริ่มใช้ | ชื่อคนทำ / วันที่ตกลงจะเปิดใช้ (เว้นว่างได้ถ้ายังไม่ตกลง) | ทีม / ทุกคน |

### แม่แบบ "รายละเอียดและขอบเขต" (ปุ่ม "ใช้แม่แบบ" ในหน้างานใส่ให้อัตโนมัติ)

```markdown
## เป้าหมาย
ทำเพื่ออะไร แก้ปัญหาอะไร ใครได้ประโยชน์

## ขอบเขต
- ทำ:
- ไม่ทำในรอบนี้:

## จุดที่เกี่ยวข้องในระบบ
หน้าจอ / เมนู / ไฟล์ / ตาราง / API

## หมายเหตุ
```

### งานย่อยที่ดี

- 3–10 ข้อต่องาน ถ้าเกิน 15 ข้อ ให้แตกเป็นหลายงาน
- ขึ้นต้นด้วยคำกริยา และตรวจได้ว่าเสร็จหรือยัง: "ออกแบบหน้าจอ", "ทำ API บันทึกผลการโทร", "ทดสอบกับทีมเทเล 2 คน"
- เรียงตามลำดับที่ทำจริง ข้อสุดท้ายมักเป็น "ทดสอบกับผู้ใช้จริง" หรือ "เปิดใช้งาน"
- ตอนติ๊กเสร็จ ใส่โน้ตสั้นๆ ว่าทำอะไรหรือหลักฐานอยู่ไหน

## 2. อัปเดตงานยังไง

1. **เริ่มงาน**: ย้ายสถานะเป็น "กำลังทำ" และถ้างานย่อยยังว่างให้ใส่ให้ครบก่อน
2. **ระหว่างทำ**: ติ๊กงานย่อยที่เสร็จ (บันทึกทันที ไม่ต้องกดบันทึก) และเขียน **อัปเดตความคืบหน้า** ในแท็บ "ความคืบหน้า / ประวัติ" อย่างน้อยวันละครั้งที่มีการทำงาน เช่น "ทำหน้า list เสร็จ พรุ่งนี้ทำ API ติดรอสิทธิ์ฐานข้อมูล"
   - อัปเดตความคืบหน้าจะต่อท้ายเป็นไทม์ไลน์ ไม่ทับของเดิม
   - อย่าเขียนความคืบหน้าลงช่อง "สรุปสำหรับผู้ชม" ช่องนั้นให้แก้เฉพาะตอนภาพรวมของงานเปลี่ยน
3. **ติดขัด**: ใส่ "สาเหตุที่ติดขัด" และบอกว่ารออะไร/รอใคร
4. **ส่งตรวจ**: ย้ายเป็น "รอทดสอบ" ใส่หลักฐาน
5. **ปิดงาน**: ย้ายเป็น "เปิดใช้งานแล้ว" ระบบลงวันที่เปิดใช้จริงให้เอง

สถานะ: 0 รอทำ · 1 กำลังทำ · 2 รอทดสอบ · 3 รอเปิดใช้ · 4 เปิดใช้งานแล้ว

## 3. แจ้งกลุ่ม Lark

แจ้งเฉพาะเรื่องที่คนในกลุ่มควรรู้: เริ่มงานใหญ่, งานย่อยสำคัญเสร็จ, ติดขัด/ต้องการการตัดสินใจ, พร้อมให้ทดสอบ, เปิดใช้งานแล้ว
ไม่ต้องแจ้งทุกการติ๊ก

- หน้าเว็บ: เลือก "แจ้ง Lark" ข้างปุ่มบันทึก หรือเลือก "ส่งเข้า Lark ด้วย" ตอนบันทึกความคืบหน้า
- คำสั่ง: เติม `--notify main` (กลุ่มจริง) หรือ `--notify test` (กลุ่มทดสอบ)
- **ทดลองระบบหรือยังไม่แน่ใจ ให้ใช้ `test` เสมอ**
- ข้อความที่ส่งมีชื่อโปรเจกต์ เลขงาน สถานะ ความคืบหน้างานย่อย ข้อความของคุณ และลิงก์เปิดงาน

## 4. สำหรับ AI agent และคนที่ใช้คำสั่ง

ขอลิงก์ถาวร **สิทธิ์แก้ไข** เฉพาะโปรเจกต์ที่ต้องทำจากผู้ดูแล (หน้า "การเข้าถึง") ห้ามใช้ลิงก์ผู้ดูแล

```text
set WORKBOARD_LINK=https://larksuite.prima49.com/#invite=…       (PowerShell: $env:WORKBOARD_LINK="…")
node scripts/wb.mjs tasks --project "Mini ERP" --open             งานที่ยังไม่จบ
node scripts/wb.mjs show 70                                       อ่านงานเต็ม + id งานย่อย
node scripts/wb.mjs sub-add 70 "ทำ API ประวัติการโทร"
node scripts/wb.mjs sub-done 70 a1b2c3d4 --note "commit 1a2b3c"
node scripts/wb.mjs note 70 "ทำหน้า list เสร็จ ต่อไปทำ API" --notify test
node scripts/wb.mjs status 70 2
node scripts/wb.mjs set 70 evidence=@evidence.md "public_summary=ปรับหน้าโทรออกให้ทีมเทเลใช้ง่ายขึ้น ตอนนี้ทดสอบกับทีม"
node scripts/wb.mjs create "Mini ERP" "หน้ารายงานยอดขายรายวัน" feature=รายงาน --sub "ออกแบบหน้า" --sub "ทำ query" --sub "ทดสอบกับทีมขาย"
```

เติม `--json` เพื่อให้ผลลัพธ์เป็น JSON ใช้ `field=@ไฟล์.md` สำหรับข้อความยาว ดูคำสั่งทั้งหมดด้วย `node scripts/wb.mjs help`
ไฟล์ `wb.mjs` ใช้ได้เดี่ยวๆ (Node 18+ ไม่ต้องติดตั้งอะไร) คัดลอกไปไว้ในโปรเจกต์อื่นได้

### ข้อความสั่ง AI agent (คัดลอกไปใส่ใน CLAUDE.md / AGENTS.md ของแต่ละโปรเจกต์)

```text
งานของโปรเจกต์นี้อยู่ใน Workboard (https://larksuite.prima49.com) อ่านและอัปเดตด้วย node <path>/wb.mjs
(WORKBOARD_LINK ตั้งไว้ใน environment แล้ว ห้ามพิมพ์ลิงก์ลง log/commit/ไฟล์)
- เริ่มงาน: `wb.mjs show <เลขงาน>` อ่านขอบเขต เกณฑ์ตรวจรับ และงานย่อยก่อนลงมือ
  ถ้างานย่อยยังว่างหรือไม่ครบ ให้เพิ่มด้วย sub-add ก่อนเริ่ม ถ้าขอบเขตว่าง ให้เขียนตาม docs/TASK-GUIDE.md แล้ว set scope=@ไฟล์
- ระหว่างทำ: ติ๊ก sub-done พร้อม --note ที่บอก commit หรือไฟล์ที่แก้ และเขียน note สรุปทุกครั้งที่จบรอบการทำงาน
- ติดขัด: set blocked_reason="…" แล้ว note อธิบาย
- ห้ามย้ายสถานะเป็น 4 (เปิดใช้งานแล้ว) เอง ให้ย้ายได้ถึง 2 (รอทดสอบ) แล้วให้คนตรวจ
- แจ้ง Lark ใช้ --notify test เว้นแต่ได้รับคำสั่งให้ส่งกลุ่มจริง
```

## 5. ไล่เติมรายละเอียดงานเก่า (นำเข้าจาก Lark 99 งาน)

งานที่นำเข้ามีแค่ชื่อและข้อความสั้นจาก Lark ให้ไล่ทีละโปรเจกต์:

1. `wb.mjs tasks --project <ชื่อ> --open` ดูงานที่ยังไม่จบ
2. ต่องาน: เขียนสรุปสำหรับผู้ชมใหม่ให้อ่านรู้เรื่อง เติมขอบเขตตามแม่แบบ แตกงานย่อยจากสิ่งที่เหลือจริง (ข้อที่ทำแล้วให้ติ๊กพร้อมโน้ตหลักฐาน)
3. งานที่ไม่ทำแล้วให้ลบ (ในหน้าเว็บ) งานที่ซ้ำให้รวมเป็นงานเดียว
